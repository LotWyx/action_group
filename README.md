# Performance Review

Система мониторинга развития технических навыков команды (Кейс 4 «Я хочу
развиваться»): годовое планирование обучения, протоколы PR-встреч (1:1) с
планированием будущих встреч и таймлайном, древовидная структура
подразделений с правами, зависящими от положения в дереве, аналитика по
прогрессу с экспортом в Excel/PDF, геймификация, уведомления ВКонтакте и
AI-анализ на GigaChat.

- **Frontend** — `action_group/`: Vue 3 + TypeScript + Vite + Pinia, иконки
  [`@lucide/vue`](https://lucide.dev). Подробности: `action_group/README.md`.
- **Backend** — `backend/`: FastAPI + SQLAlchemy (async) + PostgreSQL, JWT-аутентификация.
- **Docker** — `docker-compose.yml` поднимает всё целиком: Postgres, backend,
  и nginx с собранным фронтендом (`/api/*` проксируется на backend same-origin).

## Быстрый старт (Docker)

```sh
cp .env.example .env   # по умолчанию всё уже работает, редактировать не обязательно
docker compose up --build
```

- Фронтенд: http://localhost:8080
- API напрямую (Swagger): http://localhost:8000/docs

При первом запуске backend сам создаёт таблицы и засеивает демо-компанию —
дерево подразделений, справочник навыков, годовые планы, пара протоколов
встреч. Данные (Postgres) переживают перезапуск контейнеров в volume `pgdata`.

## Демо-доступ

| Логин       | Пароль    | Роль в дереве                                              |
|-------------|-----------|--------------------------------------------------------------|
| `admin`     | `admin`   | Администратор системы (видит всё)                            |
| `ceo`       | `ceo123`  | Руководитель компании                                         |
| `cto`       | `cto123`  | Руководитель «Разработки» **и** подчинённый CEO в его PR       |
| `back.lead` | `lead123` | Тимлид Backend, подчинённый CTO                                |
| `front.lead`| `lead123` | Тимлид Frontend                                                |
| `qa.lead`   | `lead123` | Тимлид QA                                                      |
| `a.volkov`  | `pass123` | Разработчик без подчинённых (видит только свой профиль)        |

Права нигде не хранятся как фиксированная роль пользователя — они каждый раз
вычисляются относительно открытого профиля (`action_group/src/composables/usePermissions.ts`
на фронте, `backend/app/permissions.py` на бэкенде — проверка реальная, не
только в интерфейсе): администратору доступно всё; руководителю
подразделения — все сотрудники в его поддереве дерева; остальным — только
свой профиль. Один и тот же человек (например, CTO) может одновременно
вести PR своих подчинённых и быть подчинённым в PR у вышестоящего
руководителя.

## Опциональные фичи кейса

Все три опциональных пункта из кейса реализованы, плюс три сверху по запросу:

- **Уведомления ВКонтакте** — напоминание о приближающейся плановой дате
  подтверждения навыка (раз в сутки) и уведомление сотруднику после каждой
  PR-встречи/при планировании новой. Сообщения шлёт бот сообщества VK в
  личные сообщения; каждый привязывает свой ID пользователя VK сам (карточка
  на главном экране). См. раздел ниже.
- **Планирование встреч и таймлайн** — руководитель планирует будущую
  PR-встречу (дата + заметка) прямо во вкладке «Встречи» профиля сотрудника;
  предстоящие встречи показаны там же вперемешку с историей прошедших
  протоколов, а на экране «Аналитика» — сводный список ближайших встреч по
  всей видимой команде. При сохранении протокола просроченные план-встречи
  по этому сотруднику автоматически убираются из списка предстоящих.
- **Геймификация** — бейджи-достижения в профиле сотрудника (вкладка
  «Аналитика»): «Первые шаги», «Растущий профессионал», «Эксперт», «Без
  просрочек», «План выполнен», «Активный рост». Считаются на лету из плана
  обучения и истории встреч, ничего не хранится отдельно.
- **Экспорт в Excel/PDF** — по сотруднику и по подразделению (кнопки в
  профиле сотрудника и на экране «Аналитика» у каждой строки подразделения).
  PDF — с кириллицей (шрифт DejaVu Sans), Excel — с несколькими листами
  (сводка/план/встречи/проблемы или сводка/сотрудники).
- **AI-анализ сотрудника и команды** — кнопка «AI-анализ» в профиле
  сотрудника и у каждого подразделения на экране «Аналитика»: GigaChat
  получает структурированную сводку по плану/встречам/проблемам и пишет
  характеристику прогресса, риски и рекомендации руководителю. См. раздел
  ниже.

### Уведомления ВКонтакте

Опциональная интеграция с ботом сообщества VK
([messages.send](https://dev.vk.com/ru/method/messages.send)). Чтобы включить:

1. Создайте сообщество ВКонтакте (или используйте существующее) и убедитесь,
   что вы у него именно **администратор** (не редактор/модератор — им раздел
   API недоступен).
2. В настройках сообщества откройте «Управление» → «Настройки» → «Работа с
   API» (в части версий интерфейса — «Управление» → «Дополнительно» →
   «Работа с API»), прокрутите вниз до блока «Ключи сообщества» и создайте
   ключ с правом «Сообщения сообщества».
3. Укажите его в `.env`:

   ```
   VK_BOT_TOKEN=<ключ доступа сообщества>
   ```

4. Каждый сотрудник указывает свой числовой VK ID в карточке «Уведомления
   ВКонтакте» на главном экране (узнать свой ID можно, например, через
   vk.com/id или сторонние сервисы вида vkhost.github.io) и один раз пишет
   что-нибудь сообществу бота — ВКонтакте разрешает сообществу писать в личку
   только тем, кто уже написал ему сам (или явно разрешил сообщения).

Без токена приложение работает как обычно — все вызовы уведомлений просто
становятся no-op (`backend/app/vk_notify.py`).

### AI-анализ (GigaChat)

Опциональная интеграция с [GigaChat](https://developers.sber.ru/docs/ru/gigachat)
(Сбер) — бесплатный для физлиц тариф (`GIGACHAT_API_PERS`, ~750К токенов в
год). Получите Authorization key в личном кабинете проекта GigaChat
(раздел «Авторизационные данные», уже в base64) и укажите в `.env`:

```
GIGACHAT_AUTH_KEY=<ваш authorization key>
```

Без ключа кнопки «AI-анализ» просто показывают понятную ошибку
(`backend/app/gigachat.py`), остальное приложение не затронуто.

Технические эндпоинты Сбера используют российский корневой сертификат
(«Минцифры России»), которому большинство систем не доверяют «из коробки» —
поэтому по умолчанию `GIGACHAT_VERIFY_SSL=false`. Если сертификат установлен
в доверенное хранилище контейнера — переключите в `.env` на `true`.

## Запуск без Docker (для разработки)

```sh
# backend
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
# нужен PostgreSQL с базой из DATABASE_URL (см. app/config.py)
# для PDF-экспорта нужен установленный шрифт DejaVu Sans (apt install fonts-dejavu-core)
.venv/bin/uvicorn app.main:app --reload --port 8000

# frontend (в отдельном терминале)
cd action_group
npm install
npm run dev   # проксирует /api на localhost:8000, см. vite.config.ts
```

## Структура репозитория

```
action_group/     Vue-фронтенд (Dockerfile + nginx.conf — прод-сборка за nginx)
backend/           FastAPI-бэкенд (Dockerfile)
docker-compose.yml  db + backend + frontend
.env.example        переменные окружения со значениями по умолчанию
```

## Переменные окружения (`.env`, см. `.env.example`)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | база данных | `performance_review` / `app` / `app` |
| `JWT_SECRET` | подпись токенов сессии | `change-me-in-production` |
| `CORS_ORIGINS` | источники, которым разрешено дёргать API напрямую (не через nginx-прокси) | `http://localhost:8080` |
| `VK_BOT_TOKEN` | ключ доступа сообщества VK; пусто = уведомления выключены | — |
| `VK_API_VERSION` | версия VK API | `5.199` |
| `VK_REMINDER_DAYS_AHEAD` | за сколько дней напоминать о плановой дате | `3` |
| `GIGACHAT_AUTH_KEY` | authorization key проекта GigaChat; пусто = AI-анализ выключен | — |
| `GIGACHAT_SCOPE` | тариф: `GIGACHAT_API_PERS` (физлица, бесплатно) / `GIGACHAT_API_B2B` | `GIGACHAT_API_PERS` |
